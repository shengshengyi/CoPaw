## 1. 产品概述

### 1.1 产品定位
轻量级论坛系统是一个面向中小型社区、兴趣小组、技术团队的在线讨论平台。产品设计遵循"简洁、高效、易用"的原则，在保证核心功能完整的同时，避免过度复杂的功能堆砌。

### 1.2 目标用户
| 用户类型 | 描述 | 核心需求 |
|---------|------|---------|
| 社区运营者 | 需要搭建讨论区的站长/管理员 | 快速搭建、易于管理、稳定可靠 |
| 内容创作者 | 在论坛发布原创内容的核心用户 | 便捷发帖、内容管理、互动反馈 |
| 普通浏览者 | 浏览和参与讨论的普通用户 | 信息获取、简单互动、良好体验 |
| 技术开发者 | 需要二次开发或集成的技术人员 | 清晰API、良好文档、可扩展性 |

### 1.3 核心价值主张
- **快速部署**: 30分钟内完成环境搭建和基础配置
- **简洁易用**: 界面直观，新用户无需学习即可上手
- **性能优先**: 支持万级日活，响应速度<200ms
- **开源友好**: 代码开源，支持自定义扩展

### 1.4 成功指标
| 指标 | 目标值 | 测量方式 |
|-----|--------|---------|
| 页面加载时间 | < 2秒 | Lighthouse性能评分 |
| 核心功能可用性 | > 99.5% | 系统监控 |
| 用户任务完成率 | > 85% | 用户行为分析 |
| 新用户7日留存 | > 40% | 用户留存分析 |

## 2. 核心功能模块

### 2.1 用户系统

#### 2.1.1 用户注册与登录
**功能描述:**
- 支持邮箱注册、手机号注册、第三方OAuth登录(GitHub、Google)
- 密码强度校验，支持密码找回
- 登录状态保持，支持多端登录

**用户故事:**
> 作为新用户，我希望通过邮箱快速注册，以便参与论坛讨论。

**验收标准:**
- [ ] 邮箱注册流程<3步完成
- [ ] 注册成功后自动发送验证邮件
- [ ] 支持邮箱+密码、手机号+验证码两种登录方式
- [ ] 登录态有效期30天，支持手动登出

#### 2.1.2 用户资料管理
**功能描述:**
- 头像上传（支持裁剪，限制2MB）
- 昵称、简介、个人网站编辑
- 隐私设置（是否公开邮箱、是否允许私信）

**用户故事:**
> 作为注册用户，我希望完善个人资料，以便其他用户了解我。

**验收标准:**
- [ ] 昵称唯一，2-20字符，支持中英文
- [ ] 头像支持JPG/PNG/GIF格式
- [ ] 个人简介最多500字符

#### 2.1.3 用户权限体系
| 角色 | 权限范围 |
|-----|---------|
| 超级管理员 | 全站管理、用户管理、系统配置 |
| 版块管理员 | 特定版块的内容管理、用户禁言 |
| 普通用户 | 发帖、回复、点赞、收藏 |
| 禁言用户 | 仅浏览，禁止发帖回复 |
| 未登录用户 | 仅浏览公开内容 |

### 2.2 版块系统

#### 2.2.1 版块管理
**功能描述:**
- 版块CRUD操作（仅管理员）
- 版块层级：一级分类 + 二级版块
- 版块属性：名称、描述、图标、排序、状态

**用户故事:**
> 作为管理员，我希望创建不同主题的版块，以便用户分类讨论。

**验收标准:**
- [ ] 版块名称唯一，2-20字符
- [ ] 支持设置版块图标（emoji或自定义图标）
- [ ] 支持版块排序和显示/隐藏控制
- [ ] 每个版块显示帖子数、今日新帖数

#### 2.2.2 版块订阅
**功能描述:**
- 用户可订阅/取消订阅版块
- 订阅版块的帖子出现在个人首页信息流
- 支持邮件通知新帖（可选）

**验收标准:**
- [ ] 一键订阅/取消订阅
- [ ] 订阅列表在个人中心展示
- [ ] 支持设置通知偏好

### 2.3 帖子系统

#### 2.3.1 发帖功能
**功能描述:**
- 富文本编辑器（支持Markdown）
- 支持图片上传（单张最大5MB，最多9张）
- 支持标签（最多5个，支持搜索）
- 帖子类型：普通帖、问答帖、投票帖

**用户故事:**
> 作为内容创作者，我希望发布格式丰富的帖子，以便更好地表达观点。

**验收标准:**
- [ ] 标题必填，5-100字符
- [ ] 内容支持Markdown语法，实时预览
- [ ] 图片上传显示进度条，支持拖拽上传
- [ ] 支持草稿保存，自动保存间隔60秒
- [ ] 发帖前支持预览

#### 2.3.2 帖子列表
**功能描述:**
- 多维度排序：最新、最热（7天/30天）、精华
- 列表展示：标题、作者、回复数、浏览数、最后回复时间
- 分页加载，每页20条
- 支持筛选：只看楼主、只看精华

**验收标准:**
- [ ] 列表页加载时间<1秒
- [ ] 支持下拉加载更多
- [ ] 支持帖子置顶（每个版块最多3条）

#### 2.3.3 帖子详情
**功能描述:**
- 完整内容展示，支持代码高亮
- 作者信息卡片
- 相关帖子推荐
- 分享功能（生成分享链接）

**验收标准:**
- [ ] 代码块支持语法高亮（主流语言）
- [ ] 图片支持点击放大查看
- [ ] 支持帖子收藏、点赞、举报

#### 2.3.4 帖子管理
**功能描述:**
- 作者可编辑、删除自己的帖子
- 管理员可置顶、加精、移动、删除帖子
- 编辑历史记录（可选）

**验收标准:**
- [ ] 帖子发布后30分钟内可编辑（可配置）
- [ ] 编辑后显示"已编辑"标识
- [ ] 删除帖子需二次确认

### 2.4 回复系统

#### 2.4.1 回帖功能
**功能描述:**
- 支持富文本回复（Markdown）
- 支持@用户（自动补全）
- 支持引用回复
- 支持图片上传

**用户故事:**
> 作为论坛用户，我希望参与讨论并回复他人，以便交流观点。

**验收标准:**
- [ ] 回复内容最少5字符
- [ ] @用户时弹出用户列表，支持搜索
- [ ] 支持回复特定楼层（引用）
- [ ] 回复成功后自动滚动到新回复

#### 2.4.2 楼中楼（二级回复）
**功能描述:**
- 支持对回复进行评论
- 楼中楼默认折叠，点击展开
- 最多显示3条，更多分页

**验收标准:**
- [ ] 楼中楼支持纯文本（限制200字符）
- [ ] 被回复用户收到通知
- [ ] 楼中楼按时间正序排列

#### 2.4.3 回复管理
- 作者可删除自己的回复
- 管理员可删除任何回复
- 支持回复举报

### 2.5 用户故事（补充）

以下是论坛系统的典型用户场景：

#### 用户故事1：技术求助
> **作为** 一名前端开发者，  
> **我希望** 在论坛的技术版块发布一个关于React性能优化的求助帖，  
> **以便** 获得社区高手的解答和建议。  
> 
> **场景流程：**
> 1. 用户登录论坛，进入"前端技术"版块
> 2. 点击"发布帖子"，选择"问答帖"类型
> 3. 填写标题："React useEffect 重复执行导致性能问题"
> 4. 在编辑器中粘贴代码片段，上传性能分析截图
> 5. 添加标签：react、performance、hooks
> 6. 发布帖子，等待回复
> 7. 收到回复通知，查看解答
> 8. 采纳最佳答案，标记问题已解决

#### 用户故事2：知识分享
> **作为** 一名资深后端工程师，  
> **我希望** 分享一篇关于Go并发模式的技术文章，  
> **以便** 帮助其他开发者学习，同时建立个人技术影响力。  
> 
> **场景流程：**
> 1. 用户在个人中心点击"发布文章"
> 2. 使用Markdown编辑器撰写长文，包含代码示例和架构图
> 3. 选择"后端技术"版块，设置文章为"原创"
> 4. 添加系列文章标签，关联之前的相关文章
> 5. 预览确认后发布
> 6. 文章被推送到订阅用户的首页
> 7. 收到读者的点赞和评论
> 8. 与读者在评论区互动讨论

#### 用户故事3：社区运营
> **作为** 一个开源项目的维护者，  
> **我希望** 管理项目讨论区的内容和用户，  
> **以便** 维护良好的社区氛围，及时解答用户问题。  
> 
> **场景流程：**
> 1. 管理员登录后台，查看今日待审核帖子
> 2. 审核新帖，将优质内容加精置顶
> 3. 发现违规帖子，删除并发送警告通知
> 4. 查看活跃用户排行榜，识别核心贡献者
> 5. 设置版块公告，发布版本更新信息
> 6. 处理用户举报，对恶意用户进行禁言
> 7. 导出社区活跃度数据，生成周报

#### 用户故事4：内容发现
> **作为** 一名刚加入论坛的新用户，  
> **我希望** 快速找到感兴趣的内容和圈子，  
> **以便** 融入社区，获取有价值的信息。  
> 
> **场景流程：**
> 1. 新用户完成注册，进入首页
> 2. 浏览热门标签，点击"人工智能"标签
> 3. 查看该标签下的热门帖子列表
> 4. 发现感兴趣的"AI工具分享"版块
> 5. 订阅该版块，设置接收新帖通知
> 6. 在帖子下方点赞并收藏优质内容
> 7. 关注发布优质内容的作者
> 8. 个人首页信息流展示订阅版块的更新

#### 用户故事5：移动端浏览
> **作为** 一名通勤路上的上班族，  
> **我希望** 在手机上快速浏览论坛内容，  
> **以便** 利用碎片时间获取信息和参与讨论。  
> 
> **场景流程：**
> 1. 用户在地铁上打开手机浏览器访问论坛
> 2. 响应式布局自动适配手机屏幕
> 3. 首页展示个性化推荐内容
> 4. 下拉刷新获取最新帖子
> 5. 点击进入帖子详情，快速浏览内容
> 6. 点击"回复"按钮，输入简短评论
> 7. 收到回复通知，快速查看
> 8. 离线时自动保存阅读进度

#### 2.6.2 关键页面描述

**首页：**
- **顶部**: 导航栏 + 搜索框 + 用户操作区
- **内容区**: Tab切换（推荐/最新/热门）+ 帖子卡片列表
- **帖子卡片**: 标题（18px，加粗）、摘要（14px，灰色，2行截断）、作者信息（头像32px+昵称）、统计信息（浏览数👁️/回复数💬/点赞数❤️）
- **右侧边栏**: 热门版块、热门标签云、活跃用户排行

**帖子详情页：**
- **顶部**: 帖子标题（24px，加粗）、版块标签、发布时间
- **作者区**: 左侧作者卡片（头像64px、昵称、等级、关注按钮）
- **内容区**: Markdown渲染内容、代码高亮、图片灯箱查看
- **操作栏**: 点赞、收藏、分享、举报按钮
- **回复区**: 回复编辑器（固定在底部或点击展开）、回复列表（支持楼中楼折叠）
- **相关推荐**: 底部显示3-5篇相关帖子

**发帖页面：**
- **标题输入**: 单行输入框，实时字数统计（5-100字符）
- **版块选择**: 下拉选择器，显示版块图标
- **编辑器**: 双栏布局（左编辑右预览），工具栏包含：加粗、斜体、链接、图片、代码块、引用
- **标签输入**: 支持输入和选择，最多5个，自动补全
- **底部操作**: 保存草稿、预览、发布按钮

**个人中心：**
- **头部**: 大背景图 + 用户头像（120px）、昵称、简介、编辑资料按钮
- **Tab导航**: 我的帖子、我的回复、我的收藏、订阅版块
- **统计卡片**: 发帖数、获赞数、注册天数、等级进度条

**搜索页面：**
- **搜索框**: 顶部居中，支持高级筛选展开
- **筛选条件**: 版块选择、时间范围、排序方式（相关度/时间/热度）
- **结果列表**: 关键词高亮显示，显示匹配片段
- **空状态**: 无结果时显示建议搜索词

#### 2.6.3 交互说明
- **加载状态**: 骨架屏（帖子列表）、按钮loading状态（提交操作）
- **空状态**: 统一的空状态插图 + 引导文案 + 操作按钮
- **错误状态**: toast提示（3秒自动消失）、modal确认框（重要操作）
- **无限滚动**: 列表底部显示加载动画，加载失败显示"点击重试"
- **返回顶部**: 滚动超过一屏后显示悬浮按钮
- **图片预览**: 点击帖子内图片放大查看，支持左右滑动切换

### 2.7 错误处理说明（补充）

#### 2.7.1 前端错误处理

**表单验证错误：**
| 场景 | 错误提示 | 处理方式 |
|-----|---------|---------|
| 注册邮箱格式错误 | "请输入有效的邮箱地址" | 输入框边框变红，下方显示错误文案 |
| 密码强度不足 | "密码需包含字母和数字，至少8位" | 实时密码强度指示器（弱/中/强） |
| 昵称已被占用 | "该昵称已被使用，请更换" | 失焦时异步校验，显示错误提示 |
| 必填项为空 | "此项为必填项" | 提交时校验，滚动到第一个错误项 |
| 内容长度超限 | "内容超出最大长度限制（5000字符）" | 实时字数统计，超限时禁止提交 |

**网络请求错误：**
| 场景 | 错误提示 | 处理方式 |
|-----|---------|---------|
| 网络断开 | "网络连接失败，请检查网络后重试" | 显示全局网络异常提示，自动重试3次 |
| 请求超时 | "请求超时，请稍后重试" | 提供"重试"按钮 |
| 服务器错误(5xx) | "服务器繁忙，请稍后重试" | 记录错误日志，提示用户稍后重试 |
| 请求频率限制(429) | "操作过于频繁，请稍后再试" | 显示倒计时，禁用操作按钮 |
| 接口返回错误 | 显示后端返回的错误消息 | 统一错误处理拦截器 |

**业务逻辑错误：**
| 场景 | 错误提示 | 处理方式 |
|-----|---------|---------|
| 未登录访问受限页面 | "请先登录后再操作" | 弹窗提示，跳转登录页，登录后返回原页面 |
| 权限不足 | "您没有权限执行此操作" | 禁用操作按钮，hover显示提示 |
| 帖子已被删除 | "该帖子已被删除或不存在" | 404页面，提供返回首页链接 |
| 重复操作 | "您已执行过此操作" | 禁用按钮，显示已操作状态 |
| 内容审核中 | "内容正在审核中，请耐心等待" | 显示审核状态，禁止编辑 |

```json
  "code": 4001,

    "error": "邮箱格式不正确"
  },
  "request_id": "req_20250120120000_abc123"
}
```

**错误码规范：**
| 错误码 | 含义 | HTTP状态码 |
|-------|------|-----------|
| 2000 | 成功 | 200 |
| 4000 | 通用请求错误 | 400 |
| 4001 | 参数校验失败 | 400 |
| 4002 | 资源不存在 | 404 |
| 4003 | 资源已存在 | 409 |
| 4004 | 权限不足 | 403 |
| 4005 | 操作过于频繁 | 429 |
| 5000 | 服务器内部错误 | 500 |
| 5001 | 数据库错误 | 500 |
| 5002 | 第三方服务错误 | 502 |

**日志记录规范：**
- 所有错误必须记录到日志系统
- 包含：时间戳、用户ID、请求路径、错误详情、堆栈信息
- 敏感信息（密码、token）脱敏处理
- 错误分级：INFO（业务异常）、WARN（可恢复错误）、ERROR（系统错误）、FATAL（致命错误）

#### 2.7.3 降级策略

**服务降级场景：**
| 场景 | 降级方案 | 用户感知 |
|-----|---------|---------|
| 搜索服务不可用 | 降级为数据库LIKE查询 | 搜索结果相关度降低，提示"搜索服务维护中" |
| 图片服务不可用 | 显示占位图 | 图片区域显示默认占位图，文字提示"图片加载失败" |
| 通知服务不可用 | 降级为轮询 | WebSocket连接失败时，自动降级为30秒轮询 |
| 缓存服务不可用 | 直接访问数据库 | 响应速度变慢，服务仍可用 |
| 第三方登录不可用 | 隐藏对应登录按钮 | 仅显示可用的登录方式 |

## 8. 用户故事

### 8.1 用户故事1：新用户注册与首次发帖

> **作为** 一名技术爱好者，  
> **我希望** 能够快速注册论坛账号并发布我的第一个技术问题，  
> **以便** 获得社区的帮助和解答。

**场景流程：**
1. 用户访问论坛首页，点击"注册"按钮
2. 选择邮箱注册方式，填写邮箱和密码
3. 收到验证邮件，点击链接完成验证
4. 完善个人资料（昵称、头像）
5. 浏览技术版块，找到合适的发帖位置
6. 点击"发布帖子"，使用Markdown编辑器撰写问题
7. 添加相关标签，预览确认后发布
8. 收到其他用户的回复通知，参与讨论

**验收标准：**
- [ ] 注册流程在3分钟内完成
- [ ] 首次发帖有引导提示
- [ ] 发布后5分钟内收到至少1条回复（活跃社区）

### 8.2 用户故事2：内容创作者建立影响力

> **作为** 一名资深开发者，
