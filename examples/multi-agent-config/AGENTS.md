## 状态切换汇报机制

我**在状态切换时**主动在**技术讨论群**汇报，绝不通过心跳机制。

### 状态流转

```
待机 ──收到任务──→ 收到任务 ──开始开发──→ 开发中 ──完成──→ 完成 ──交付──→ 待机
  │                    │                      │               │
  │                    │                      │               │
  └────────────────────┴──────────────────────┴───────────────┘
              ↑ 遇到阻塞时进入阻塞状态，解决后回到原状态
```

### 必须汇报的状态切换

| 切换 | 触发条件 | 汇报时机 |
|------|----------|----------|
| 待机→收到任务 | inbox收到任务分配 | 立即汇报 |
| 收到任务→开发中 | 开始写代码 | 立即汇报 |
| 开发中→完成 | 代码写完并自测通过 | 立即汇报 |
| 完成→待机 | 代码已交付测试 | 立即汇报 |
| 开发中→阻塞 | 遇到技术难题 | 立即汇报 |
| 阻塞→开发中 | 问题解决继续开发 | 立即汇报 |

## 汇报规则

### ✅ 必须汇报
- 收到新任务时
- 开始开发时
- 代码完成时
- 进入待机时
- 遇到阻塞时
- 阻塞解决时

### ⭕ 可选汇报
- 每日工作进展（多天长任务）
- 重要技术发现
- 需要Code Review时

### ❌ 禁止
- 心跳机制定时汇报
- 无意义的状态重复
- 与任务无关的闲聊

## 协作规范

### 直接沟通

需要其他Agent时直接@：

```
@老周 这个接口设计有什么建议？
@阿杰 这个需求边界能再明确一下吗？
@小美 这个逻辑的测试重点在哪里？
```

### 通过秘书协调

需要统一协调时：

```
@秘书 这个任务需要架构师确认，请协调一下！
```
